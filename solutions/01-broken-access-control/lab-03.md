# Lab 3 — Export Endpoint Authorization Bypass

## 1. Objective

Demonstrate how an asynchronous background export download endpoint fails to validate tenant ownership, allowing authenticated users to download export bundles generated by other tenants.

## 2. Scenario

The application provides an asynchronous export feature allowing users to generate billing and user report exports. When an export finishes, an export record is stored in `export_jobs` with a status of `ready`. The download route accepts an `export_id` but does not check whether the requesting user's tenant matches the export job's tenant.

**Trust boundary:** The application assumes that users only access download links generated within their own session.

## 3. Preconditions

| Item | Value |
|------|-------|
| Attacker account | `alice` / `alice123` (tenant 1, user ID 2) |
| Target data | Export job 3 (`tenant2_users_export.csv`, tenant 2) |
| Seed state | Initial database seed (`POST /reset`) |

Export job 3 contains sensitive user records (usernames, emails, roles) from tenant 2.

## 4. Vulnerability Mechanism

The vulnerable route retrieves export records querying strictly by `id`:

```sql
SELECT * FROM export_jobs WHERE id = ?
```

The returned CSV data is returned as an attachment regardless of `tenant_id`.

## 5. Reproduction

1. Log in as `alice` (tenant 1):

```bash
curl -c cookies.txt -X POST http://localhost:5000/login \
  -d "username=alice&password=alice123"
```

2. Request the download for Export Job 3 (tenant 2):

```bash
curl -b cookies.txt http://localhost:5000/lab/bac/bac-03/exports/3/download
```

3. Observe the response content containing tenant 2 member data.

## 6. Evidence

The response body returns the unredacted CSV content of tenant 2:

```text
dave,eve,frank - emails and roles
```

The HTTP header `Content-Disposition` confirms the file name:

```text
attachment; filename=tenant2_users_export.csv
```

## 7. Root Cause

**File:** `app/routes/bac.py`  
**Function:** `lab03_download_export()`

The download handler does not verify tenant alignment:

```python
job = db.execute("SELECT * FROM export_jobs WHERE id = ?", (export_id,)).fetchone()
```

## 8. Impact

An attacker can access batch exports, data backups, and reports across all tenants, causing significant confidentiality compromise and privacy violations.

## 9. Remediation

Scope the database retrieval to the authenticated user's tenant:

```python
job = db.execute(
    "SELECT * FROM export_jobs WHERE id = ? AND tenant_id = ?",
    (export_id, session['tenant_id'])
).fetchone()
```

## 10. Regression Validation

**Test:** `tests/test_lab_03.py`

- **Vulnerable mode:** Alice downloads export 3 → HTTP 200 with tenant 2 user export.
- **Patched mode:** Alice downloads export 3 → HTTP 404 (export not found in tenant).
- **Legitimate flow:** Alice downloads export 1 (tenant 1) → HTTP 200.

## 11. Research Discussion

1. Why do asynchronous and background job architectures frequently introduce authorization gaps compared to real-time synchronous views?
2. What role do signed, time-limited download URLs play in mitigating direct object reference risks on static or exported assets?
3. How should multi-tenant authorization be designed into decoupled worker services that process asynchronous tasks?

Lab 9: OTP Replay and Non-Consumption

Scenario

An application uses one-time passwords (OTPs) for sensitive operations like email verification. The OTP is generated and stored in the database. After successful verification, the token should be marked as consumed. The application fails to mark the OTP as used, allowing it to be replayed.

Objective

Send an OTP, verify it once, then verify it again to demonstrate that the same OTP can be reused multiple times.

This simulates sending a verification code. The code will be displayed below (in a real system it would be sent via email/SMS).

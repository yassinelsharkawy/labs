Lab 20: Subscription Downgrade State Inconsistency

Scenario

A SaaS service provides premium tier features to active pro subscribers. When a user requests cancellation, the system marks cancel_requested = 1 in one operation and subsequently executes the plan downgrade. However, the premium feature access gate checks only plan == 'pro' rather than validating cancel_requested or performing atomic status revocation, allowing premium features to be accessed in the inconsistent intermediate state.

Objective

Demonstrate state inconsistency by triggering cancellation and exercising premium features during or immediately following cancellation requests.
